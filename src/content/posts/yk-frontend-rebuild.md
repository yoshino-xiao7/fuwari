## # 前言

三天前写了那篇《亦可YK 前端推倒重写了》，当时首页刚跑起来，很多页面还没填。今天这篇是来报进度的：**yk.yukiryou.icu 的应用端前端重构已经完成了。**

说"完成"指的是，能正常用的页面都已经替换成新版，交互流程走得通，不再是半成品状态。细节当然还可以继续打磨，但至少不用再给别人说"你先别用这个页面，还没做完"了。

## # Antigravity 引导式设计

这次新前端的设计流程和之前完全不一样。

以前的做法基本是：我自己脑子里想一个大概的样子，然后去写代码，写着写着发现不对，改一改，再跑起来看，再改。循环多了之后很容易陷进去——觉得哪里不舒服但说不清楚，改来改去反而越改越乱。

这次完全用 **Antigravity** 来做分段式迭代。流程变成了：

1. 先让 Antigravity 出一版页面；
2. 跑起来之后截图，**哪里不好直接圈出来**；
3. Antigravity 根据圈注的位置和我的描述去改；
4. 改完再截图再看，觉得可以了就进入下一个模块。

这种方式比自己在脑子里空想高效太多了。尤其是 UI 设计这种我本来就不擅长的事情，语言描述经常词不达意。但截图圈一下就不一样——"这个按钮太大了""这段间距太挤了""这个颜色和背景撞了"，圈出来之后意思非常明确，AI 改起来也准。

而且这种方式天然就是分段式的。我不需要一开始就把所有页面的设计想好，做到哪个模块就设计哪个模块，每个模块内部快速迭代到满意为止。整体节奏是"光速"的，三天时间从空白到全部应用端页面替换完毕，效率拉满。

## # 为什么老前端一直不满意

老前端的问题我其实早就知道，但一直没下决心彻底解决。

最核心的感受就一个：**它看起来像一个管理后台，不像一个面向用户的应用。**

这跟最开始的定位有关。亦可YK 的前身是开发者 API 工具，Web 端最早就是为了管理 API 密钥、查看调用日志、配置回调地址这些功能而做的。后来图库、音乐、AI 绘画这些用户向的功能加进来，但整体的页面外壳还是那套控制台式的布局：左边一栏导航、右边一大片内容区、顶部一条工具条。

之前也重构过，但效果不好。原因很简单——重构的时候还是在旧骨架上改，换了颜色、调了间距、改了图标，但页面结构没有动。用户打开之后，第一眼看到的还是那种"后台管理系统"的气质。AI 顺着已有代码修改的时候也是同理，它会倾向于保留原来的结构，往上面做局部优化，结果就是改完了还是那个味道。

所以上次那篇才说"直接推倒重写"。这次重写不只是换了代码，更重要的是换了设计思路：先定好页面应该长什么样，再去实现，而不是在旧代码里修修补补。

## # 导航栏：自己最满意的设计

如果非要说这次重构最满意的一个点，那就是**新的导航栏**。

老前端的导航方式就是传统的侧边栏——页面左边竖着一排菜单项，每个菜单点开跳转。这种布局本身没毛病，但它对页面的侵入性很强：导航栏常驻在那里，挤占内容区的宽度。尤其是在移动端，侧边栏不是收起来就是变成一个抽屉，交互怎么做都不太自然。

新的导航栏设计我反复调了好几版，最后做出来的效果我自己非常满意：

- **对页面侵入性低**——不会常驻占位，内容区拿到了更大的空间；
- **用户使用起来方便**——该找到的东西能很快找到，不需要翻来翻去；
- **移动端和桌面端体验一致**——不用针对不同屏幕尺寸做两套交互逻辑。

具体长什么样、交互效果怎样，我就不贴截图了，大家直接去 [yk.yukiryou.icu](https://yk.yukiryou.icu) 体验就好。自己点开试一试，比我在这里文字描述有效得多。

## # 管理端还得做

应用端的前端重构告一段落，但管理端还没动。

管理端和应用端不一样：应用端是给普通用户看的，管理端是给我自己用的——管理图库审核、查看用户数据、配置系统参数、处理 AI 绘画队列这些。管理端对"好看"的需求没那么强，但对"好用"的要求反而更高，因为我自己天天都在用。

这块排在后面做。应用端先稳住，管理端慢慢来。
