## 更新概述

**雪涼云 2.6.0 Beta2** 是 AI 绘图服务上线后的第一轮体验修正版。

上一个版本已经把“云端提交任务、本机 Worker 出图、云端保存历史和审核广场”这条主链路跑通了；Beta2 的重点则是解决“能用，但还不够好用”的问题。

本次更新主要包括：

- AI 绘图页面交互优化。
- 服务在线状态和排队状态展示。
- 自然语言提示词生成改为本机 Worker + Ollama 处理。
- LoRA 和角色预设选择器升级。
- 新增和整理一批角色预设。
- 新增双角色绘制 Beta。
- 修复双角色手绘区域污染画面的问题。
- 本机 Worker 控制台和健康检查增强。

整体设计仍然保持不变：云端后端是唯一业务入口，本机 `setu_ai_wife` 只作为主动轮询任务的 AI Worker，本机端口不需要暴露到公网，生成图片继续通过云端写入 OSS。

## AI 绘图页面体验优化

绘图入口仍然是：

```text
/dashboard/ai-draw
```

本次页面体验做了多处调整：

- 自然语言描述变为可选，不再强制填写。
- 只填写正向提示词也可以直接生成图片。
- 自然语言生成提示词和正式生图流程拆开。
- 生成出的正向/反向提示词可以继续编辑。
- 修复画幅选择、生成提示词按钮、角色卡片和注入 tags 区域的重叠问题。
- 服务不可用时禁用生成按钮，并展示不可用原因。
- 管理员在非开放时间仍可生成，只要 Worker 在线即可。

画幅预设调整为更适合 SDXL 动漫模型的尺寸：

| 画幅 | 尺寸 |
| --- | --- |
| 竖屏人像 | `832x1216` |
| 横屏场景 | `1216x832` |
| 大头照 | `1024x1024` |
| 手机壁纸 | `832x1472` |

生成按钮现在会根据身份和模式展示实际消耗：

- 单角色普通用户：`50` 积分。
- 双角色普通用户：`100` 积分。
- 管理员：免费。

## 服务状态和队列可见性

Beta2 新增 AI 服务状态展示。

用户进入绘图页面后，可以看到当前服务是否可用，以及 Beta 开放时间。

前端会轮询：

```text
/ai/status
```

展示内容包括：

- Worker 是否在线。
- 当前是否在开放时间内。
- 开放时间。
- 下次开放时间。
- 队列数量。
- 运行中数量。
- 上传中数量。
- 预计等待时间。
- 服务不可用原因。

Beta 开放时间：

```text
08:30-22:30
```

普通用户和普通 API Key 需要同时满足：

- 当前时间在开放时间内。
- Worker 在线。

管理员和管理员名下 API Key 只要求 Worker 在线，不受开放时间限制。

## 提示词生成改为 Worker + Ollama

自然语言提示词生成现在不再由云端直接处理，而是改为走本机 Worker 的 Ollama。

新增提示词翻译任务队列：

```text
ai_prompt_translation_job
```

工作流程：

1. 用户输入自然语言描述。
2. 云端创建提示词翻译任务。
3. 本机 Worker 主动领取任务。
4. Worker 调用本机 Ollama 生成英文正向/反向提示词。
5. 结果回写云端。
6. 前端展示生成结果，用户可以继续编辑。

本机 Worker 会结合提示词知识库：

```text
setu_ai_wife/config/prompt_knowledge.json
```

这能改善中文角色名、作品名和别名转换，减少把中文原文直接塞进英文 tag prompt 的情况。

同时，本次移除了默认强塞的通用质量词堆叠，避免反复出现过度模板化的提示词。

如果 Ollama 不可用或超时，前端会显示明确错误，不再把失败结果伪装成正常翻译。

## LoRA 和角色预设选择器升级

LoRA 和角色预设不再只是普通下拉框，而是升级为资产选择器。

新选择器支持：

- 左侧目录树按类型和分类分组。
- 右侧卡片展示显示名、预览图和摘要。
- 点击卡片选择。
- 点击详情查看完整元信息。

支持展示的元信息包括：

- 显示名。
- 文件名。
- 触发词。
- 推荐强度。
- 适配 checkpoint。
- 说明。
- 预览图。
- 分类。
- 分类类型。

LoRA 默认值始终是“不使用 LoRA”，避免误选模型影响生成结果。

选择角色预设后，会自动注入角色 tags，不再要求用户必须手动填写正向提示词才能提交。

checkpoint 文件名也支持友好显示名，目前默认模型显示为：

```text
二次元动漫 WAI
```

## 双角色绘制 Beta

Beta2 新增双角色生成模式。

前端支持在单角色 / 双角色之间切换。

双角色模式支持：

- 角色 A 预设。
- 角色 B 预设。
- 第一 LoRA。
- 第二 LoRA。
- 第二角色 ID。
- 可选角色布局参考。

后端新增生成模式：

```text
SINGLE
DUAL
```

双角色计费规则：

- 普通用户双角色：`100` 积分。
- 管理员双角色：免费。
- API Key 按 Key owner 身份计费。
- Worker 或系统失败仍会自动退款。

为了降低双角色被单角色提示词污染的概率，双角色 prompt 会自动过滤：

- `1girl`
- `solo`
- 其他明显偏单角色的 tags

Worker 也会默认降低双角色 LoRA 强度上限，减少两个角色特征互相串味。

## 双角色手绘区域策略修正

早期 Beta2 尝试过区域 mask、inpaint 和区域 conditioning，但实际效果并不稳定，容易出现：

- 两个角色融合成一个角色。
- 角色 B 被擦掉。
- 左右两侧各自生成两个人。
- 多手、多脚增加。
- 手绘线条或遮罩影响画面。
- 用户绘制区域污染生成效果。

因此当前默认策略调整为：

```dotenv
DUAL_CHARACTER_STRATEGY=auto
```

默认行为：

- 不画区域时：普通双角色单次生成。
- 同时画出 A/B 区域时：只提取大致位置、上下左右和靠近关系，转成普通布局提示词。
- 默认不再使用 ComfyUI `ConditioningSetMask`。
- 默认不再使用二次 inpaint。

保留实验开关：

```dotenv
DUAL_CHARACTER_STRATEGY=mask-conditioning
DUAL_CHARACTER_STRATEGY=inpaint
```

但这两个策略目前只建议用于排查或实验，不作为普通用户默认方案。

## 本机 Worker 控制台

本机首页从“本机绘图工作台”调整为 Worker 控制台。

控制台展示：

- ComfyUI 状态。
- Ollama 状态。
- 本机 FastAPI 状态。
- 云端 API 配置状态。
- Worker Token 配置状态。
- 模型目录状态。
- 默认 checkpoint 是否存在。
- checkpoint / LoRA / VAE / 角色预设数量。

新增本机健康检查接口：

```text
GET /api/health
```

一键启动脚本支持：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_cloud_all.ps1 -Restart
```

云端上传成功后，默认会清理本机临时图片，减少 `outputs/` 长期堆积。

## 当前已知限制

- 双角色仍是 Beta 能力。
- 两个角色 LoRA 同时加载时，基础 ComfyUI 节点无法做到真正的 LoRA 区域隔离。
- 双角色仍可能出现角色特征串味。
- 手绘 A/B 区域当前只作为布局参考，不是精准分割遮罩。
- 亲密互动、遮挡严重、上下叠放等构图仍依赖模型理解和 prompt 质量。
- 如果后续要继续提升双角色稳定性，可能需要接入 attention couple / regional LoRA 类自定义节点，或引入自动分割后的局部修复流程。
- Ollama 不会永久学习，本地知识库只是每次请求前注入上下文，不会修改模型权重。
