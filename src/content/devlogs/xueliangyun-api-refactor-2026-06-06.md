## 更新概述

这次更新主要围绕 **雪涼云 API 项目近期重构** 做一次阶段性记录。

本轮工作分成两部分：

- **Console 前端重构已完成并合入主分支**：重点优化性能、移动端体验、请求稳定性、后台重页面和音乐播放器。
- **Setu API 后端重构路线已整理完成**：围绕 `/setu/v2` 主链路、鉴权计费、外部服务调用、搜索性能、缓存限流、数据库迁移和测试基线做后续规划。

简单来说，前端这边已经完成了一轮比较完整的工程治理；后端这边则进入“按痛点逐步闭环”的重构阶段。

---

## Console 前端重构交付

本轮前端重构不改变现有后端接口语义，也不调整真实 API 路径，仍然基于当前的 Vue 3、Vue Router、Pinia、Naive UI 技术栈推进。

### 性能与工程治理

- 新增统一环境配置，集中管理 API Base URL、站点地址和 Mock 开关。
- 对 Vite 构建 chunk 进行拆分，将 Vue、图标、图表和工具类依赖从主入口中分离。
- 新增构建预算检查脚本，用于约束路由 chunk 和入口 gzip 体积。
- 移除全局完整注册 Naive UI 的方式，降低公共入口压力。
- 将重型播放器逻辑从全局布局中拆出，完整播放器迁移到 `/dashboard/music`。

### API 响应与请求稳定性

- 新增统一响应解包工具，兼容 Axios 原始响应和已解包后的直接数据。
- 清理多个页面中重复的 `unwrap(res)` 逻辑，减少接口返回结构变动带来的维护成本。
- 新增请求 guard、分页资源、错误处理、异步状态和本地存储 JSON 等 composable。
- 解决快速切页、筛选或刷新时旧请求覆盖新数据的问题。
- 页面卸载后避免请求继续回写状态。

### 移动端与响应式体验

- 新增统一断点 composable，集中提供移动端、平板、桌面端和紧凑布局判断。
- 控制台和后台布局统一抽屉侧栏。
- API Key、收藏夹、积分调用、收藏夹广场、后台列表等页面改为更适合移动端的卡片与底部操作区。
- 弹窗、表格、播放器、MV 浮窗等组件增加宽度约束，减少横向滚动和遮挡。
- 页面底部留白结合 `safe-area-inset-bottom`，避免移动端底部播放器或系统手势区域遮住关键按钮。

### 用户流程与后台页面

- 登录、注册、找回密码和验证码链路完成移动端与 Mock 兼容治理。
- Dashboard 概览、API Key、开发文档等高频页面完成统一响应解包和移动端约束。
- 收藏夹、公开收藏夹、收藏夹广场、积分调用等页面增加 loading、empty、error 状态。
- 后台用户管理、图片管理、删除申请、IP 黑名单、后台概览和音乐 Token 管理完成稳定性治理。
- Pixiv 新增图片任务历史修复卡死问题，并调整为最近任务优先展示。

### 音乐播放器重构

- `/dashboard/music` 成为完整播放器页面。
- 音乐页改为主播放台、播放队列和歌词区域组合。
- 主播放台包含封面、进度、主控按钮和音质切换。
- 歌词区改为内部滚动，避免影响整页滚动。
- 全局迷你播放器在桌面端显示为低干扰窄条，移动端默认小胶囊。
- 迷你播放器支持收起、展开、进入完整音乐页和打开播放队列弹层。
- MV 浮窗宽度改为响应式限制，减少小屏幕下的溢出。

## 后端重构路线

后端重构的目标不是一次性“大搬家”，而是围绕当前项目痛点逐步闭环：性能、安全、稳定、可维护、可观测、可部署和可验证。

### 第一阶段：`/setu/v2` 主链路拆分

`/setu/v2` 是当前最核心、访问频率最高、也最容易放大问题的接口。后续会优先拆分这条链路：

- 请求参数归一化独立出来，统一处理 `num`、`r18`、`size`、`proxy` 等参数。
- 查询策略独立出来，区分 pid、描述搜索、普通随机、多 anchor 抽样等路径。
- 结果组装独立出来，继续保持 tags 和 urls 批量查询，避免回退到 N+1。
- 图片 URL 代理转换独立出来，统一处理 size 选择和代理域名替换。
- `SetuService` 回归主流程编排，不再承载所有细节。

验收重点包括：响应字段不变、不回退到 `ORDER BY RAND()`、空结果退款逻辑不变、核心单测补齐。

### 第二阶段：鉴权、计费、退款、日志统一

当前 API Key、Session、扣费、退款和请求日志分布在 controller 与 interceptor 中，后续会统一为更清晰的访问上下文和计费审计服务：

- 引入统一访问上下文，描述调用者身份、来源、API Key、用户 ID、Session 和 IP。
- 统一 API Key、Session、匿名访问解析。
- 扣费、退款、积分流水集中到计费服务。
- 请求日志统一入口，避免 `/usage` 出现重复统计风险。
- 常规日志不输出 API Key、JWT、cookie、验证码和签名密钥。

### 第三阶段：外部服务 Client 化

Pixiv 和网易云代理都依赖外部服务，后续会将它们封装为独立 client：

- Pixiv 任务创建、查询、取消、健康检查统一封装。
- 网易云代理调用、主备地址切换和缓存读取统一封装。
- 外部请求统一超时、重试、降级和异常类型。
- 接入 Micrometer 指标，区分 Pixiv 与网易云调用耗时。
- 失败日志保留 endpoint、status、duration，但不泄露 cookie、token 或完整敏感 URL。

### 第四阶段：tag / keyword 搜索性能优化

当前 tag 和 keyword 模糊搜索仍可能在数据量变大后触发慢查询。后续会优先在 MySQL 和表结构内优化：

- 增加 tag 标准化字段。
- 为常用精确 tag 查询建立索引。
- 将模糊 keyword 搜索和随机抽样拆成两步：先取候选 ID，再做多 anchor 抽样。
- 后续根据数据量再评估是否需要引入全文索引、倒排索引表或外部搜索服务。

### 第五阶段：缓存、限流、迁移与测试

后续还会继续补齐这些基础能力：

- 为热门 tag 候选 ID、状态统计和总数统计增加短 TTL 缓存。
- 将反爬与限流策略配置化，便于线上调整。
- 继续使用 Flyway 管理数据库迁移和索引变更。
- 梳理删除图片、收藏、审核、删除申请等链路的数据一致性。
- 扩展 `SetuServiceTest`、计费测试、审计日志测试和接口回归用例。
- 增加 SQL 文本测试，固定禁止核心查询回退到 `ORDER BY RAND()`。
